Ch 3-1 · Linear List Concepts

Linear List 分類與四大基本操作：General vs. Restricted

[[Sue-DS-Ch03-LinkedLists]]
白話入門 把資料排成一列就是 Linear List。如果「隊伍中間可以隨時插隊、抽走任何人」，叫 General List；如果規定「只能從頭尾兩端進出」，像排隊結帳（Queue）或疊盤子（Stack），就叫 Restricted List。

專業線性串列兩大分類（Figure 3-2）

  • General List（一般串列）：可在任意位置插入與刪除。
    • Unordered (Random) List：無排序限制（實務較少用）。
    • Ordered List：依關鍵欄位 key 維持遞增／遞減順序。
  • Restricted List（受限串列）：僅能在端點增刪。
    • FIFO (Queue)：先進先出（前端出、後端進）。
    • LIFO (Stack)：後進先出（僅限頂端 Top 進出）。

專業四大基本操作比較

操作說明與限制
Insertion加入新元素；Ordered List 須維持 key 順序。
Deletion定位並移除元素；Array 需搬移後續元素。
Retrieval讀取元素且不破壞串列（Queue/Stack 取出即移除）。
Traversal用迴圈依序處理全部元素；不適用於 Restricted List。

Ch 3-2 · 結構權衡

Array vs. Linked List 的核心權衡：隨機存取 vs. 動態增刪

[[Sue-DS-Ch03-LinkedLists]] · [[array-vs-linked-list-and-stack]]
白話入門 Array 把資料並排在連續記憶體，知道第 50 格一秒就能算出地址；Linked List 的車廂分散在記憶體各地，靠「下一節地址小紙條」串聯，插隊只要改紙條，但找人必須從頭一節一節問過去。
比較維度Array（陣列）Linked List（鏈結串列）
記憶體配置連續配置（Contiguous）非連續動態配置（節點間無實體相鄰關係）
搜尋演算法有序時可用 Binary Search（O(logn)）無法使用 Binary Search，僅能 Sequential Search（O(n)）
中間插入／刪除後續元素必須逐一搬移（Shifting，O(n)）找到位置後只需改指標（O(1)），免搬移資料
額外空間成本預留未使用陣列槽位每個節點須額外儲存指標欄位 link

常見誤區為什麼有序 Linked List 不能用 Binary Search？

Binary Search 必須靠索引計算「正中間元素」的記憶體位址並於 O(1) 跳過去；Linked List 即使資料依 key 排序，仍沒有隨機存取能力，想找第 n/2 筆還是得從 pHead 走 n/2 步！

Ch 3-2 · Self-Referential Structure

Linked List 資料結構解剖：Head Metadata 與 Node

[[Sue-DS-Ch03-LinkedLists]] · [[linked-lists]]
白話入門 Linked List 分成兩種方塊：「火車頭管理表（Head）」只負責記車廂總數 count 與第一節在哪 head；「資料車廂（Node）」一半裝貨物 data，另一半放指向下一節車廂的箭頭 link。

專業結構關鍵與指標角色

  • Self-Referential Structure：每個 node 內含指向同型別結構的指標 link。
  • Metadata（Head）：除 count、head 外，常擴充 pos（走訪位置）與 pLast / rear（指向尾節點加速搜尋）。
  • createList 初始化：務必設 head = null、count = 0，清除記憶體殘留值。
list
  count  <integer>      // 串列節點總數
  head   <node pointer> // 指向第一節點 (空串列為 null)
end list

node
  data   <dataType>     // 含搜尋鍵 key 與資料欄位
  link   <node pointer> // 指向下一個同型別節點
end node

Linked List 插入：四種情境化簡為「兩大類」與接線順序

[[Sue-DS-Ch03-LinkedLists]] · [[linked-lists]]
白話入門 加掛車廂有「空車、最前、中間、最後」4 種情況，但只要看前面有沒有車（pPre 是否為空）就剩 2 類！掛勾必先「① 新車勾住後車，再 ② 前車改勾新車」，順序顛倒後段列車會直接斷軌！ 
allocate(pNew); if (overflow) return false

if (pPre null) { // 第一類：空串列或最前
  pNew->link = list.head;  list.head = pNew
} else {         // 第二類：中間或最後(pPre->link即null)
  pNew->link = pPre->link; pPre->link = pNew
}
list.count = list.count + 1;  return true

Ch 3-3 · Algorithm 3-3 deleteNode

Linked List 刪除（deleteNode）與記憶體回收（recycle）

[[Sue-DS-Ch03-LinkedLists]] · [[linked-lists]]
白話入門 卸下中間一節車廂，只需讓「前一節車廂的掛勾直接跳過它、勾住下一節」，再把卸下的車廂報廢回收（recycle）！四種位置（唯一、首、中、尾）同樣只判斷 pPre 是否為空。 
algorithm deleteNode (ref list, val pPre, val pLoc, ref dataOut)
  dataOut = pLoc->data       // 先備份回傳資料
  if (pPre null)             // 刪首節點或唯一節點
    list.head = pLoc->link
  else                       // 刪中間或尾節點
    pPre->link = pLoc->link
  end if
  list.count = list.count - 1
  recycle(pLoc)              // 統一放條件外避免重複寫

專業Algorithm 3-3 設計重點

  • 先找再刪：呼叫端必先透過 searchList 取得合法的 (pPre, pLoc) 才呼叫 deleteNode。
  • 邏輯移除 vs. 實體回收：改動 link 只是邏輯移出串列；若忘記 recycle(pLoc) 會造成 Memory Leak。
  • 結構化簡：把 count - 1 與 recycle 移出 if/else 區塊外，讓兩條分支共用收尾邏輯。

Ch 4-1 · Basic Stack Operations

從 General 走向 Restricted：Stack（堆疊）與 LIFO 原則

[[Sue-DS-Ch04-Stacks]] · [[stacks-and-backtracking]]
白話入門 Stack 就像洗好疊起來的一疊盤子（或硬幣）：新盤子只能「疊在最上面（Push）」；要拿也只能「從最上面拿走（Pop）」，或「偷看最上面那塊的花色（Stack Top）」。最後放的永遠最先拿！

1. Push（推入）

專業將新元素加入 Top。若空間已滿無法推入，觸發 Overflow。

2. Pop（彈出）

專業移除 Top 元素並回傳給呼叫端。若對空堆疊執行，觸發 Underflow。

3. Stack Top（檢視）

專業複製回傳 Top 資料但不刪除該節點；空堆疊時同樣觸發 Underflow。

核心直覺LIFO（Last-In, First-Out）軌跡範例

若依序推入 {5, 10, 15, 20}，則 20 位於 Top；連續 Pop 取出順序必為 {20, 15, 10, 5}。此「最後放入最先處理」的順序反轉特性，正是第 12–15 頁四大應用的基礎。

Stack 應用一＆二：資料反轉（十進位轉二進位）與括號剖析

白話入門 十進位轉二進位時，一直除以 2 得到的餘數順序剛好「頭尾顛倒」，全丟進 Stack 再倒出來就變正了！檢查程式碼括號也是：看到左括號先收進口袋（Push），看到右括號就拿一個左括號出來配對（Pop）。

應用一資料反轉：decimalToBinary（Alg 4-10）

Stack 應用三（上）：Infix 轉 Postfix 運算式轉換

Stack 應用三（下）：Postfix 表達式求值與 Pop 順序陷阱

[[Sue-DS-Ch04-Stacks]] · [[stacks-and-backtracking]]
白話入門 算後序式就像「把數字先疊在盤子上，看到加減乘除符號時，再從最上面抓兩塊數字出來算，算完放回最上面」！但要小心：減法與除法有順序之分，先抓出來的是「右邊」的數字！ 
if (expr[i] is operand)
  pushStack(stack, expr[i])  // 推入數值
else
  popStack(stack, operand2)  // 先彈右運算元！
  popStack(stack, operand1)  // 再彈左運算元
  value = calculate(operand1, expr[i], operand2)
  pushStack(stack, value)

常見誤區減法／除法的致命順序

例如後序式 8 2 -：8 先入棧在底、2 後入棧在頂。遇 - 時若誤把第一次 Pop 的 2 當左運算元，就會算成 2 - 8 = -6；務必記得「先 Pop operand2、再 Pop operand1」才是正確的 8-2=6！

[[Sue-DS-Ch03-LinkedLists]] · [[Sue-DS-Ch04-Stacks]] · [[array-vs-linked-list-and-stack]]
白話入門 沒有萬能的資料結構！資料量固定又常按編號查用 Array；常從中間插隊或刪除用 Linked List；需要「後進先出」反轉、算式解析或走迷宮反悔就用 Stack！
使用場景推薦結構關鍵理由
頻繁隨機存取／有序二分搜尋ArrayO(1) 定址、O(logn) 搜尋、OS Spatial Locality 極佳
頻繁中間動態增刪、長度未知Linked ListO(1) 改指標免搬移（依需求選 Singly / Doubly）
狀態回溯、括號／運算式處理Stack (ADT)容量可估選 Array 版最快；不可估選 Linked List 版

核心結論四大必記重點

  • 雙指標收斂：searchList 同時回傳 (pPre, pLoc)，讓 insertNode／deleteNode 四情境收斂為兩大類；插入必先接後繼再改前驅。
  • 變體防護：Circularly 搜尋須防繞圈（startAddress）；Doubly 插入須注意 Alg 3-22 課堂修正。
  • Data Hiding & Pop 陷阱：Stack 透過標準介面隱藏實作；Postfix 求值必先 Pop operand2。
  • 跨章延伸：Array 連續配置有利 CPU Cache 與 OS 虛擬記憶體減少 Page Fault（[[virtual-memory-and-paging]]）。
